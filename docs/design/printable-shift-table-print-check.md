# 印刷用シフト表の紙面確認記録

`/shifts/print` の紙面を実際の印刷出力で確認した記録（2026-09-07）。データ変換のテスト（`test/printable-shift-table.test.ts`）は行の組み立てのみを保証するため、文字サイズ・余白・改ページはこの記録を根拠とする。

## 確認条件

- ブラウザ: Google Chrome 152.0.7977.76（macOS）
- 用紙: A4 縦（210mm × 297mm）
- 余白: CSS の `@page { margin: 12mm }`（Chrome の余白設定「デフォルト」で適用される値）。紙面の内容領域は 186mm × 273mm
- 倍率: 100%
- 背景のグラフィック: オフ（Chrome の既定）。列見出しの網掛けは印刷されない前提で確認した
- ヘッダーとフッター: オフ
- 確認方法: 実装の CSS（`PrintableShiftTable.module.css`）と行生成（`printable-table.ts`）をそのまま使った紙面を Chrome の印刷経路（`Page.printToPDF`）で PDF 化し、ページごとの出力と各要素の実寸を確認した

## 紙面の寸法（実測）

| 項目                           | 値                                                   |
| ------------------------------ | ---------------------------------------------------- |
| 表題「2026年1月 シフト表」     | 18pt                                                 |
| 出力日時                       | 9pt                                                  |
| 表の本文（日付・種別・担当者） | 11pt / 行送り 1.4（1行あたり約 5.4mm）               |
| 列見出しに併記する年月         | 8pt                                                  |
| 日付列の幅                     | 28mm（「12（月・祝）」を折り返さずに収める）         |
| 担当者のいない日の行の高さ     | 12.3mm（手書き用の最小高 9mm + 上下余白 1.5mm ずつ） |
| 割り当てのある日の行の高さ     | 12.3mm 〜 46.7mm（種別数・人数に応じて伸びる）       |

## 確認したデータと結果

| データ                                                | ページ数 | 結果                                              |
| ----------------------------------------------------- | -------- | ------------------------------------------------- |
| 31日・両部門・複数種別・長い名前・週末は4名/種別      | 3        | 文字欠け・はみ出しなし。日付行の分断なし          |
| 31日・両部門・週末のみ1〜2名                          | 2        | 同上                                              |
| 31日・スキーのみ                                      | 2        | 単一部門では欄が広く、折り返しが減る              |
| 31日・スノーボードのみ                                | 2        | 同上                                              |
| 31日・両部門・1日あたり3〜5名（想定される通常の規模） | 2        | 折り返しがほとんど発生せず、各日1〜2行に収まる    |
| 空月（割り当てゼロ・28日）                            | 2        | 全日付が残り、全欄が手書き用の空欄になる          |
| 月末のみ稼働（12月26日以降のみ）                      | 2        | 稼働前の日付も空欄で残る                          |
| 1日に5種別 × 13名                                     | 4        | その日の行（139mm）は分断されず次ページへ送られる |
| 区切りのない長い英字名（38文字）                      | 3        | 欄内で折り返す（`overflow-wrap: anywhere`）       |

いずれの出力でも、操作ボタン・アプリのヘッダー・サイドバーは印刷されず、1ページ目に対象年月と出力日時、2ページ目以降にも列見出しと対象年月が繰り返し印刷されることを確認した。

## 判明した制約

- 31日の月は、11pt の文字と手書き用の行の高さを保つ限り A4 縦 1 枚に収まらない。全日付（31行 × 12.3mm = 381mm）だけで内容領域の 273mm を超えるため、空月でも 2 ページになる。1 枚に収めるには文字を 8pt 程度まで縮小するか手書き欄を削る必要があり、読みやすさを優先して複数ページを許容する方針とした。
- 1日分の内容がページの内容領域（約 260mm、スキー欄で約 47 行 ≒ 12種別 × 23名相当）を超える場合のみ、日付行がページをまたいで分断される。担当者の省略や文字の縮小は起きず、継続ページでは日付欄が空欄になる。実運用で想定される規模ではないため、ブラウザの自動分断に任せる（2026-09-07 ユーザー確認済み）。
- 列見出しの網掛けは Chrome の既定設定では印刷されない。白黒でも列見出しと日付行を区別できるよう、見出し下の罫線を 2px に太くして識別の主体としている。
