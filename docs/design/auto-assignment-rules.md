# シフト自動割当の判断ルール

2026-11-04の担当者ヒアリングに基づく。対象は部門ごとの一般レッスンを想定した自動割当。実装の公開入口は `solveAutoAssignments`、振る舞いの検証は `test/auto-assign-solver.test.ts`。

## 目的

必要人数を確保し、勤務の確実性と過密勤務の回避を優先したうえで、部門内のシーズン勤務日数を近づける。出勤可能日数が多い人へ比例配分する方式は採用しない。

## 申告と資格

- 勤務不可（UNAVAILABLE）は割り当てない。
- 要調整（AVOID）は勤務が確実ではないため、勤務可能な候補だけでは必要人数を満たせない場合に限って使う。
- 申告がない日は勤務可能と扱う。未登録・アカウント未連携・申告レコードなしによる優遇、減点、要確認は付けない。将来月の申告なしも、将来の勤務機会の確約とは解釈しない。
- 資格は指導員（tierRank 1）・準指導員（2）を同じ区分、認定指導員（3）を別区分とする。指導員と準指導員の間に優先差はない。
- 必要資格と候補者の資格の一致は必須。複数資格がある人は上位区分で判定する。現行の汎用ランク設定で3以降が存在する場合も認定側の区分として扱うため、一般レッスン以外への適用時は資格設定を確認する。

## 比較する順序

次の順序は固定し、下位条件の改善で上位条件を逆転させない。日数換算の重みや日数差のしきい値は使わない。

1. 勤務不可・必要資格なし・同日重複を候補から除外する。同日重複は全部門・全シフト種別にまたがって禁止する。
2. 必要人数まで埋める。候補不足なら不足人数と理由を返す。3人目も要調整で埋める。
3. 要調整の割当数を最小にする。勤務可能な人がいれば、勤務日数や資格構成で不利でも勤務可能を優先する。
4. 4連勤以上を避ける。2・3連勤には優先度の差を付けない。代わりの候補がいなければ4連勤以上も割り当てる。
5. 部門内のシーズン累計勤務日数を近づける。
6. 同点なら、認定指導員のみの枠を避ける。次に、2名以上の枠では両区分を混ぜる。3人目を認定にすること自体は、勤務日数の平準化より優先しない。
7. なお同点なら、再現可能な乱数で選ぶ。同じ入力・シードでは同じ提案となる。別案が必ず存在するとは限らない。

## 集計と月全体の評価

- 勤務日数・連勤とも当該部門内、全シフト種別を対象とする。同日複数枠の既存勤務は1日と数える。
- シーズン範囲は既存の `seasonRangeForDate` を利用し、その範囲の保存済み勤務と対象月の未保存編集を含める。将来月に保存済みの勤務があれば含め、未設定の将来勤務は推測しない。
- 自動割当の対象枠は白紙から置換するため、その枠の元の勤務は集計と重複判定から除く。対象外の未保存編集は保持し、判断に含める。
- 連勤は暦日で連続する勤務を数える。月境界をまたぐ前後の勤務もつなげ、最終提案全体で評価する。
- 連勤の評価値は各連勤区間の `max(連勤日数 − 3, 0)` の合計。4連勤は1、5連勤は2となり、長い連勤ほど避ける。保存済み勤務は変更しない。
- 公平性の評価値は候補者全員の累計勤務日数の二乗和。総割当数が同じ案同士でこれを小さくし、勤務日数の偏りを抑える。出勤可能日数による目標補正はしない。
- 月0日に独立した減点は付けない。機会が少ない人のための将来予測も行わず、シーズン累計の平準化で扱う。

## ユースケース

以下は、特記しない限り勤務可能・必要資格あり・同日重複なし。累計は当該部門のシーズン勤務日数。

| 状況                                             | 割当例と理由                                                     |
| ------------------------------------------------ | ---------------------------------------------------------------- |
| 勤務可能な認定20日と、要調整の準指導員2日        | 認定を選ぶ。勤務の確実性が最優先。認定のみなら要確認             |
| 3人必要で勤務可能2人、要調整1人                  | 3人を割り当て、要調整の勤務を要確認とする                        |
| 準指導員6日と認定5日                             | 認定を選ぶ。1日差でも勤務日数を優先                              |
| 準指導員20日と認定2日                            | 認定を選び、認定のみなら要確認                                   |
| 準指導員5日と認定5日。認定1人が同枠に入る想定    | 準指導員を選び、認定のみを避ける                                 |
| 指導員5日と準指導員5日                           | 資格の上下では差を付けず、他の条件も同じなら同点                 |
| 今回4連勤目になる人が累計5日、前日休みの人が20日 | 前日休みの人を選ぶ。連勤回避が勤務日数より優先                   |
| 今回3連勤目になる人が累計2日、前日休みの人が5日  | 累計2日の人を選ぶ。3連勤までは差を付けない                       |
| 4連勤目になる勤務可能者と、前日休みの要調整者    | 勤務可能者を選ぶ。要調整の回避が連勤回避より優先                 |
| 候補者が1人しかおらず今回4連勤目                 | その人を割り当てる。連勤は割当禁止条件ではない                   |
| 12/30・12/31・1/2が勤務済みで1/1へ追加           | 4連勤になるため、代わりがいれば他の人を選ぶ                      |
| 他部門で多く勤務しているが当該部門は少ない       | 当該部門の勤務日数で比較する。ただし同日に他部門勤務があれば除外 |
| 未連携の人と申告レコードがない人                 | どちらも申告がない日は勤務可能。登録状態で差を付けない           |
| 必要3人に対し適格候補が2人しかいない             | 2人を提案し、不足1人と理由を表示                                 |

## 提案と管理者確認

認定指導員のみの構成は1人枠を含めて許容するが、必ず「要確認」を付ける。要調整を含む勤務にも確認理由を付ける。要確認は許可済み・出勤確定を意味しない。

確認理由は提案の `reviewReasons` で返し、ステージ反映時に勤務枠の備考へ「要確認: …」として記録する。保存・再読み込み後も確認できる。管理者は確認後、備考を編集できる。手動で構成を変更した場合の自動再判定は行わないため、備考も確認して更新する。

必要人数の初期値は平日2人、土日祝3人。画面の人数指定で変更でき、日本の祝日・振替休日も休日人数を使う。

## 探索の限界と検証

日付順の初期案を20回生成し、最良案を1枠内の人の置換と日付間の交換で改善する。候補抽出で絶対条件を維持し、全体の評価値が辞書順で改善する変更だけを採用する。改善探索は最大20,000評価で終了する。局所探索のため大域的な最適解を保証しない。

合意したユースケースを公開ソルバーのテストで検証する。ステージ反映・未保存編集の統合も別の公開関数のテストで検証する。将来ルールを変更する際は、この文書と対応テストを同時に更新する。
