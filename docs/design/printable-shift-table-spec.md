# 印刷用シフト表の仕様

機能要件は合意済み。既存コードとADRに基づく実装・テスト方針を併記する。

## Problem Statement

シフトの確認はシステム上を基本としているが、IT操作に不慣れな人や紙での確認を好む人には、スクールに掲示できるシフト表が必要である。現場で急ぎ担当者を決めた際には紙に書き込むこともある。無限スクロールの閲覧画面をそのまま印刷すると、未取得の日付の欠落や紙面の読みにくさが生じる。

## Solution

シフト閲覧画面から対象月と部門を選び、別タブに月間の印刷用シフト表を表示する。ページの印刷ボタンからブラウザの印刷画面を開き、紙への印刷やPDF保存を行う。A4縦・白黒印刷を前提に全日付を縦に並べ、担当者がいない欄には手書きできる余白を残す。読みやすさを優先し、必要なら複数ページにする。

## User Stories

1. 掲示担当者として、閲覧画面から印刷を開始したい。月間シフト表を容易に用意するため。
2. 掲示担当者として、モーダルで対象月を選びたい。必要な月を出力するため。
3. 閲覧者として、画面内の一番上に見えている日付の月を初期選択にしたい。閲覧中の予定をそのまま印刷するため。
4. 閲覧者として、モーダルを開いた後は対象月を固定したい。意図せず選択が変わるのを防ぐため。
5. 掲示担当者として、両部門・スキーのみ・スノーボードのみを選びたい。人数や掲示場所に合わせるため。
6. 掲示担当者として、標準で両部門を同じ表に載せたい。少人数の場合の用紙の無駄を抑えるため。
7. 掲示担当者として、自分のみの閲覧設定に関係なく全担当者を載せたい。掲示から他の担当者が漏れるのを防ぐため。
8. 掲示担当者として、スクロールで未取得の日も含めた月全体を出力したい。予定の欠落を防ぐため。
9. 紙の利用者として、月初から月末まで全日付を見たい。カレンダーとして使うため。
10. 現場担当者として、担当者がいない日は完全な空欄にしたい。急ぎ決めた担当者を手書きするため。
11. 現場担当者として、未割り当ての文言や不要な種別枠を省きたい。記入場所を確保するため。
12. 紙の利用者として、日付の右に部門ごとの担当者を見たい。担当部門を判別するため。
13. 紙の利用者として、各部門内で勤務内容の種別ごとに名前をまとめて見たい。誰がどの勤務を担当するか確認するため。
14. 紙の利用者として、シフトの説明文を省いた表を見たい。必要な担当情報を読み取りやすくするため。
15. 年配の利用者として、小さすぎない文字で読みたい。無理なく確認するため。
16. 掲示担当者として、A4縦で出力したい。一般的な用紙で掲示するため。
17. 紙の利用者として、収まらない月は複数ページにしたい。文字の縮小を避けるため。
18. 紙の利用者として、同じ日付の内容を同じページで見たい。担当情報を一緒に確認するため。
19. 紙の利用者として、白黒でも曜日と祝日が分かる表記にしたい。色に頼らず予定を把握するため。
20. 紙の利用者として、対象年月と出力日時を見たい。対象期間と印刷物の新旧を判断するため。
21. 掲示担当者として、別タブで印刷用ページを開きたい。元の閲覧位置を保つため。
22. 掲示担当者として、内容を確認してから印刷ボタンを押したい。準備が整ってからブラウザの印刷画面を開くため。
23. 紙の利用者として、操作ボタンやナビゲーションのない紙面を使いたい。予定と手書き欄を広く使うため。
24. 掲示担当者として、ブラウザからPDF保存も選びたい。必要に応じてファイルとして扱うため。
25. 掲示担当者として、月末から営業する月も同じ月単位で出力したい。印刷操作をシンプルに保つため。

## Implementation Decisions

- 既存のシフト機能に、印刷条件モーダル・別タブの印刷用ページ・印刷用のデータ整形とスタイルを追加する。一般の閲覧画面と同じ認証を適用し、公開閲覧用ページにはしない。
- 対象月と部門を別タブへ渡し、別タブ側で既存の月次カレンダー取得機能から月全体を読み込む。無限スクロールの取得済みページや個人絞り込みを印刷データの入力元にしない。
- 既存の月次APIは対象月の全シフトと割り当て済み表示名を返す。新規のDBテーブル・マイグレーション・印刷専用APIは不要とする。
- 日付は暦月の全日を生成して昇順に並べる。両部門では日付・スキー・スノーボードの構成とし、単一部門では対象部門の欄のみを置く。
- 種別は登録された勤務内容の区分を用い、Seedの4種に固定しない。既存APIの種別順・担当者表示名を利用し、利用設定から外れた種別の既存割り当ても落とさない。
- 各部門内で「一般レッスン：田中・佐藤」のように表示し、種別間で改行する。説明文は表示せず、担当者がいない勤務枠は種別名ごと省く。全ての勤務枠で担当者がいなければ完全な空欄を残す。
- 空欄の表示は印刷上の表現であり、シフトの作成・削除や稼働日の定義を変更しない。
- A4縦で月1枚を基本とするが、1枚に収めるための文字縮小は行わない。複数ページを許容し、通常の行は日付単位で改ページする。具体的な文字サイズ・行の高さは実際の紙面で読みやすさと手書きの余地を確認して調整する。
- 曜日を文字で表示し、祝日は既存の日本の祝日判定を使って「21（月・祝）」のように示す。罫線・見出しは白黒でも識別できるようにする。
- 対象年月・出力日時を掲載する。出力日時はシフトの最終更新日時を意味しない。
- 印刷用ページの印刷ボタンからブラウザの印刷機能を呼び出す。自動では開かず、紙面から操作ボタンやアプリのナビゲーションを除外する。独自のページ分割プレビューやPDF生成機能は作らない。
- 閲覧中の日付は既存のURL連動を活用するが、現在の表示割合ベースの検出が画面最上部の日付と一致するとは限らない。印刷開始時の最上部の日付で月を決め、モーダル内の選択は以後自動変更しない。日付が見えない場合はURLの有効な日付をフォールバックに用いる。
- データ取得中・取得失敗時には正常な空月として表示せず、状態を明示して印刷を開始できないようにする。取得に成功して割り当てがない月は、全日付と空欄の表を表示する。

## Testing Decisions

以下は既存ADRに沿ったテスト方針案である。内部コンポーネント構成や型で保証される内容ではなく、利用者から観測できる出力を検証する。

- 既存のHono HTTP境界と実D1を利用するシフト表示統合テストを主なデータ取得の検証境界とする。対象月の範囲・全部門の割り当て・既存認証のテストを再利用し、今回の変更で不足が生じる場合のみ追加する。APIに変更がなければ同じテストを重複追加しない。
- 新規の検証境界は「月次データと印刷条件から、印刷する日付・部門・種別・担当者の行を作る処理」にまとめる。既存のシフト集計・日付ユーティリティのVitestテストを手本に、28／29／30／31日、年越し、対象部門、担当者のない枠、複数種別、月末のみの割り当て、割り当てゼロの月を検証する。
- 手動のブラウザ確認では、モーダルの初期月と変更、月境界の最上部判定、個人絞り込みの非継承、別タブ表示、取得中・失敗時の挙動、印刷ボタンを確認する。
- ブラウザの印刷プレビューまたはPDF出力で、31日・両部門・複数種別・長い名前・3〜5名程度の日・空欄を含むデータを確認する。A4縦、白黒、文字の見やすさ、手書き欄、複数ページ時の日付行の分断、文字欠け、操作UIの非印刷を確認する。
- 既存のADRに従い、自動E2Eや重いブラウザモック、新規テスト基盤は導入しない。データ変換のテストだけで印刷レイアウトを検証済みとは扱わない。

## Out of Scope

- 週単位・任意期間の出力、個人別の印刷絞り込み。
- 種別ごとの固定枠、説明文、未割り当ての表示。
- システム内での紙面への直接編集、手書き内容の自動取り込み。
- 印刷物の履歴保存、公開共有リンク、確定・承認フロー。
- 独自の印刷プレビュー、サーバーでのPDF生成、プリンター制御。
- A4一枚への強制縮小、シフトのライフサイクルや認証モデルの変更。
