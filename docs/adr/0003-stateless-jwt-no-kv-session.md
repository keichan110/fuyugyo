# 認証はステートレス JWT を継続し、KV セッションは採用しない

## Status

accepted

## Context

移行計画の初稿では「KV ベースのセッション管理（isolate 横断のため）」を提案していた。しかしこの前提は誤りである。「isolate 間で共有できない」問題はインメモリ Rate Limit には当てはまるが、JWT には当てはまらない。JWT はステートレスで署名検証のみで完結し、isolate をまたいでも問題なく、DB/KV アクセスを一切要さない。

このシステムでは **JWT トークンそのものがログインセッション**であり、サーバー側に別のセッションストアは存在しない。KV セッションを導入すると毎リクエストで KV read が1回増え、コスト・レイテンシは下がるどころか上がる。

## Decision

- **ステートレス JWT（jose）を継続**する。KV フルセッションは採用しない。
- 権限は ADMIN / MANAGER / MEMBER の3段ロールを JWT クレームで保持。
- **JWT 有効期限を 48h → 12h（≒1営業日相当）に短縮**する。即時失効（秒単位）は要件ではないため、翌営業日には無効化が必ず効く状態で実用十分とする。
- 即時失効が必要になった場合に限り、後日 KV ブラックリスト（失効操作時のみ書き込み、通常時 read 不要）を検討する。フルセッションストアには戻さない。

## Consequences

- 認証検証は外部アクセス0でメモリ内完結。CF Workers 上で最安・最速。
- ユーザー無効化（isActive=false や権限変更）は最大12時間反映が遅れる。スクール運営の性質上許容する。
