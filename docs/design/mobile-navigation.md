# モバイルナビゲーション

関連: [Issue #305](https://github.com/keichan110/fuyugyo/issues/305)

## 構成

モバイル幅（Mantine の `sm` 未満）ではアプリ共通ヘッダーを表示せず、画面下部に主要導線を固定する。ページのタイトルや操作欄は本文内に残す。PC のヘッダーとサイドバーは維持する。

| ロール         | 下部タブ                                             |
| -------------- | ---------------------------------------------------- |
| MEMBER         | ホーム / シフト表 / シフト希望 / その他              |
| MANAGER・ADMIN | ホーム / シフト表 / シフト希望 / シフト管理 / その他 |

インストラクターとの連携状態によってタブ数や順序は変えない。未連携時はシフト希望だけを無効化し、「要連携」と無効理由の読み上げラベルを付ける。ホームから連携できる。直接シフト希望ページへアクセスした場合も、カレンダーの代わりに連携案内を表示する。解除直後はカレンダーを破棄し、再連携時は本人の情報で初期化する。

シフト表は未連携でも閲覧できる。「自分だけ」の絞り込みは既存どおり連携が必要。MEMBER の閲覧対象は公開済み・配置ありの枠で、MANAGER・ADMIN の閲覧対象は従来どおり。

「その他」は既存の左側ドロワーを使う。主要タブにある項目を省き、それ以外のメニューとアカウント操作を表示する。既存の権限条件は変更しない。招待メニューの表示とページのアクセス条件の不一致も、この変更では扱わない。

シフト管理では専用タブ、その他の管理画面では「その他」を選択状態にする。選択状態は文字とアイコンの色で示し、背景色は変えない。タブラベルは320px幅でも折り返さず1行で表示する。ドロワー内の項目を選ぶと閉じる。ドロワーを開くだけでは未保存変更の確認を出さず、実際に画面を離れるときに既存の破棄確認を使う。

## 下部の固定領域

- タブ本体の高さは64px。iOS の下部 safe area を別途加える。
- `AppShell.Footer` と本文の余白に同じ高さを適用する。
- 未保存バーは Footer の上に配置し、本文末尾が両方の固定要素に隠れないよう余白を追加する。
- `viewport-fit=cover` を指定し、タブの左右にも safe area を確保する。
- 入力要素へのフォーカスと VisualViewport の150pxを超える縮小を組み合わせ、キーボード表示中はタブを隠す。ピンチズームは判定対象から除外する。
- ホーム・シフト表では下へ32px読み進めるとタブを下へ退避し、上へ24px戻すかページ先頭付近へ移動すると再表示する。編集画面には適用しない。
- ページ遷移後と「その他」のドロワー表示中はタブを表示する。日付クエリだけの更新では表示状態をリセットしない。
- 退避中も本文の下余白は変えず、タブへのフォーカスと操作を無効化する。動きを減らす設定ではアニメーションを省く。
- シフト表の「上へ戻る」は、表示中のタブ高と安全領域を考慮して配置する。タブの出入りと位置を連動させ、切り替え途中も重ならないようにする。
- 印刷時はタブを表示しない。

## 検証

`e2e/smoke/mobile-navigation.e2e.ts` で、ロール別メニュー、未連携時のタブ維持と直接アクセス、320px幅、現在地表示、印刷時非表示、未保存バーとの非重複、破棄確認、連携解除・再連携、キーボード表示領域の変化、スクロール方向によるタブの出入り、「上へ戻る」との非重複を確認する。

キーボードの自動テストは Chromium 上で VisualViewport の変化を再現する。iOS の実際のキーボードや safe area の再現ではない。

### 実機での確認事項（未実施）

- iOS の LINE 内ブラウザと Safari で、ホームインジケーターとタブが重ならず、本文末尾までスクロールできること。
- キーボードの開閉・入力欄間の移動・キーボードだけを閉じる操作で、タブが適切に退避・復帰すること。
- キーボード表示中のモーダル内の入力・反映操作と、画面回転後の表示が正常なこと。
- 未保存バーが出ている状態でも、保存・キャンセルと下部タブを操作できること。
