# 必要人数を Shift とは別テーブルに保存し、行なしを未設定・0を開講予定なしとする

## Status

accepted

## Context

自動割当の人数（平日2名・土日祝3名）は実行時だけの一時値で保存されず、割り当て担当者は「その日に何名必要で、いま何名足りないか」を画面で判断できなかった。日付 × 部門 × シフト種別ごとの必要人数を永続化し、配置人数との充足状況を日別・月別に見せたい。

一方、ADR 0010 は Shift を割り当て駆動の暗黙ライフサイクルにし、「開講だが0名」という第3状態を却下している。必要人数を Shift に持たせると、人が決まっていない開講枠のために 0 名の Shift を残すことになり、この方針と衝突する。

## Decision

**必要人数は `shifts` とは別のテーブル（`shift_staffing_requirements`）に、日付 × 部門 × シフト種別を一意キーとして保存する。**

- 行がない枠は**未設定**、`required_count = 0` は**開講予定なし**を表す。`required_count` は nullable にしない。
- Shift とは独立して保存する。全員を外して Shift が消えても必要人数の行は残る。
- 割り当て保存 API に必要人数の差分を同梱し、割り当てと同じ単一バッチで保存する。必要人数だけの保存は割り当てに触れない。
- 既存データのバックフィルは行わない。根拠なく既存の枠を 0 名や充足済みとみなさないためである。
- 閲覧 API（カレンダー・アジェンダ・出勤状況など）は引き続き **Shift がある日だけ**を返す。必要人数は割り当て担当者向けの管理画面でのみ使う。

### ADR 0010 への影響

ADR 0010 が却下した「開講だが0名」の第3状態は、Shift ではなく必要人数の側で表せるようになる。これに伴い、ADR 0010 の「休校/開講の状態は割り当ての有無と常に一致する」は次のように一部更新する。

- 稼働日は「1件以上の Shift が存在する、または必要人数1名以上の枠がある日」、休校日は「Shift が1件もなく、必要人数1名以上の枠もない日」とする（CONTEXT.md）。
- 必要人数1名以上でまだ誰も割り当てていない枠は「未割り当て枠」であり、休校日ではない。
- Shift の生成・削除のライフサイクル（最初の割り当てで生成、全員を外すと削除）自体は変えない。

## Considered Options

- **`shifts` に必要人数の列を足す**: テーブルは増えないが、未設定の日や0名の日を表すために人のいない Shift が必要になり、ADR 0010 のライフサイクルを壊す。却下。
- **`required_count` を nullable にして未設定を NULL で表す**: 「行なし」と「NULL の行」の二重の未設定が生まれる。行なしを未設定とし、解除は行の削除で表す。却下。
- **既存の Shift がある枠へ、現在の配置人数や初期値でバックフィルする**: 実際の必要人数の根拠がなく、未設定を充足済みに見せてしまう。却下。

## Consequences

- 画面は必要人数と配置人数から 未設定／開講予定なし／不足／充足（過員を含む）を導く。必要人数が0名で配置がある日は充足として扱う。
- 自動割当は日別の必要人数（未保存の値を含む）が1名以上の日だけを対象にし、未設定日を初期値で補うことはしない。平日2名・土日祝3名は、必要人数を一括設定するときの初期値になる。0名の日は自動割当の対象外だが、手動の割り当ては可能である。
- 必要人数は勤務可用性（本人の申告）とは別概念である。
- テーブル追加のみで既存テーブルは変更しない。リモート D1 へのマイグレーション適用は通常のデプロイ手順に従う。
