# ヘッダーのみ + ロールベースのナビゲーション構成を採用する

## Status

accepted

## Context

ナビゲーション構成として、サイドバー常時表示・ボトムナビゲーション・ヘッダー+ドロワー等の選択肢があった。利用者のユースケースを整理した結果、一般ユーザー（Instructor）はシフト確認がほぼ唯一の操作であり、管理者もシフト管理が中心でマスタ管理は低頻度という実態が判明した。モバイルファーストだが PC でのシフト編集にも対応する。

## Decision

**Mantine AppShell のヘッダーのみ構成**を採用し、ロールに応じてナビゲーション項目を出し分ける。

- **一般ユーザー**: ヘッダーにロゴ + アバター（ログアウト）のみ。ページ遷移はダッシュボード（`/`）内の動線で完結
- **管理者**: 上記に加え、管理メニュー（ドロワー or ドロップダウン）を配置。3グループ構成:
  - シフト運用: シフト管理
  - マスタ管理: 部門 / 資格 / シフト種別 / インストラクター
  - ユーザー管理: ユーザー / 招待
- サイドバー・ボトムナビゲーションは**採用しない**

一般ユーザーのナビゲーション対象画面が実質2つ（ダッシュボード + シフト一覧）しかなく、専用のナビゲーション領域を常設する必要がない。管理者も低頻度のマスタ管理のためにサイドバーを常時表示するのは画面占有面積の無駄。

## Consequences

- 将来、一般ユーザー向けの画面が増えた場合（勤務可能日入力等）、ナビゲーション構成の再検討が必要になる。現時点ではダッシュボードに動線を集約することで対応する想定。
