# T3 Code と worktree による並列開発

## 開始手順

T3 Code でタスクごとに独立した worktree を作成し、その worktree のターミナルで実行する。

```bash
pnpm run worktree:setup
pnpm run dev
```

T3 側に作成後のセットアップコマンドを登録する場合も `pnpm run worktree:setup` を使う。
`.worktreeinclude` のコピーはツールによって対応が異なるため、セットアップ自身でもプライマリチェックアウトから `.env` と `.dev.vars` を補完する。既存ファイルはコピーで上書きしない。

セットアップは以下を行う。

1. dev と E2E のポートを割り当てる。プライマリは既定で5173と5180、追加 worktree は5200以降と15200以降。割り当ては `.dev-port` / `.e2e-port` に保存し、再実行しても維持する。
2. ローカル環境変数を準備し、`APP_URL` を開発URLに合わせる。元の設定がなければ `.env.example` から `.dev.vars` を生成し、JWT秘密鍵をランダムに作る。LINEの秘密値は別途設定する。
3. 依存関係をインストールし、その worktree のローカルD1に既存マイグレーションを適用する。
4. 新規DBに認証用招待とデモデータを投入する。再実行で既存DBのデモデータをリセットしない。

`.wrangler`、`node_modules`、ビルド成果物は共有しない。DBファイルのシンボリックリンクも使わない。既存のコピー機能で `.wrangler` 全体をコピーしている場合は、その設定を解除する。既存DBはセットアップでは削除しない。

## ブラウザと認証

Cookieはポートで分離されないため、手動確認では worktree ごとに独立したブラウザプロファイルを使う。シークレットウィンドウを複数開くだけでは同じセッションを共有することがある。

`db:seed:auth` はログイン用アカウントではなく、LINEログイン用の招待 `dev-invite` を作る。LINEログインを手動確認する場合は `.dev.vars` のチャネル設定と、LINE Developers のコールバックURL登録が必要。コールバックURLは表示された開発URLに `/api/auth/line/callback` を付ける。

E2Eは専用のダミー認証とブラウザコンテキストを使い、実LINEログインを必要としない。

## テストとポート競合

```bash
pnpm run test
pnpm run test:e2e:smoke
```

E2Eは `.e2e-port` を参照し、各 worktree の `.wrangler/e2e-state` を再作成する。同じ worktree 内でE2Eを複数同時実行しない。

ポート払い出しは共通Gitディレクトリのロックで直列化する。外部アプリがポートを使用している場合、サーバーは別ポートに自動退避せず起動に失敗する。不要なプロセスを終了するか、停止中にポートファイルを空いている番号へ変更してセットアップを再実行する。

ロックは通常終了・SIGINT・SIGTERMで解放する。SIGKILLなどで残った場合も、同じホストの所有プロセスが終了していることを確認できれば自動回収する。経過時間だけで実行中のロックを奪わない。他ホストのロック・所有者が不明なロックやPIDが再利用された場合は自動回収せずタイムアウトするため、所有者が実行中でないことを確認してから手動で対処する。

## 統合と終了

スキーマ変更が重なった場合は、後から統合するブランチで最新mainを取り込み、`drizzle/` のSQLとメタデータの整合性を確認する。既存の適用済みSQLを安易に書き換えない。本番へのマイグレーションやdeployはエージェントでは実行しない。

作業終了時は、その worktree の開発サーバーを止めてからT3側で worktree を削除する。ポートは現存する worktree の設定から判断するため、削除済み worktree の割り当ては再利用される。

セットアップとロックの回帰テストは `pnpm run test:scripts` で実行する。`pnpm run test` の先頭でも実行するため、CIでも必ず検証される。
