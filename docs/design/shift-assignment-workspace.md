# シフト割り当て画面の配置方針

対象: #247。2026-11-07 にサンプルで比較し、3領域に分ける方針と、以下のモバイル操作を承認。

## 領域と操作

部門 → シフト種別 → 日付（枠）の順に操作する。

- **カレンダー**: 配置者名を残して当月を俯瞰する。不足・未保存を表示する。名前・人数・備考アイコンを含むセル全体を日付選択に使い、ここでは人を選択しない。
- **編集フォーム**: 選択枠の候補選択・必要人数・備考を扱う。人の分析対象は候補行の「分析」から選ぶ。割り当てチェックとは独立した操作とする。
- **分析**: カレンダーとフォームの下で開閉できる。「月全体」「選択枠」「選択した人」を切り替える。月全体から不足枠へ、人の配置日からその枠へ移れる。

PC（1200px以上）はカレンダーとフォームを左右に並べ、フォーム右上の「×」で閉じると月を広く見渡せる。再表示はカレンダーの日付選択で行い、専用の表示ボタンは置かない。分析はその下に置く。フォームは高さを制限して候補をスクロールできる。

モバイル（768px以下）は **日付リスト → フォーム → 分析を縦積み** にする。画面切り替えや全画面モーダルは使わない。月移動のヘッダーは共有し、日付ごとに配置者名を折り返して表示する。日付行全体で枠を選び、配置人数・必要人数と充足状態、未保存、備考も確認できる。月のリストは高さを制限してスクロールでき、フォームが遠くなりすぎないようにする。768pxを超える狭い画面は月間カレンダーの下にフォーム・分析を並べる。多人数の候補はフォーム内でスクロールでき、備考が候補数に比例して遠くならないようにする。

候補は1行にまとめ、右端に短い「分析」ボタンを置く。選択中は「解除」に変え、カレンダーの強調表示の横からも解除できる。分析領域の開閉は見出し右側の上下矢印で行う。

人を選んだときは、当月の配置日と名前を、PCはカレンダー上、モバイルは日付リスト上で強調する。日別の表示上限で名前が省略された場合も、日付セルの面で配置日が分かる。人の選択は枠を切り替えても保持し、月・部門・種別を変えたら解除する。

## 集計の境界

この画面の俯瞰は、当月の配置の並び（連日・週末への集中）に気づくためのもの。勤務日数の総量を1か月だけで評価しない。

分析「選択した人」の数値（当月・シーズン勤務日数、連勤、連続勤務週数）は、全部門・全種別の勤務を月をまたいで集計する。シーズン（9/1〜8/31）内で打ち切り、未保存の編集を含む。同日に複数枠へ入っていても1日と数える。保存済みの月外分はAPI、当月分は画面の現在案から合成する。対象範囲と期間は数値に併記する。

当月の配置のタイムラインは、表示中の部門・種別を●、同部門の別種別を○、別部門を◆（部門色）、勤務なしを―で描き分け、凡例を常時表示する。他部門・他種別の勤務は読み上げでも「部門 / 種別」で伝える。

この全部門横断の表示負荷は、自動割当の公平性評価（表示中の部門内の勤務日数）とは範囲が異なる。今回の表示改善で自動割当の方針は変えない。

カレンダー・分析には同じ未保存の配置を渡す。既存の一括保存・編集破棄・画面移動時の確認・自動割当対象日の選択を維持する。

## 保存前の点検（#242）

2026-11-08 の検討で、自動割当の実行前後の履歴は保持せず、保存済みと現在案を比較する方針へ変更した。保存後に確認ステップは追加しない。

- 「月全体」は人数不足・勤務可否（要調整・勤務不可の配置）・4連勤以上・資格構成の件数カードを表示する。件数は対象月・表示部門・種別の枠数で、同じ枠は複数項目に該当しうる。カードで日別一覧を絞り込める。
- 日別一覧に不足人数・対象者・要確認理由を表示し、選ぶと「選択枠」に切り替えて編集フォームへ移動する。同じ要確認事項を選択枠の先頭に表示し、手動修正後も現在案から再計算する。日付を選んでフォームを開くと選択枠へ、閉じると月全体へ連動して切り替える。
- 連勤は自動割当の評価に合わせ、同部門・全種別・シーズン内の月外勤務を含む。「選択した人」の全部門横断の負荷表示とは対象範囲が異なる。既存コンテキストに月外勤務がない配置者は、連勤未判定として表示する。
- 必要人数・資格の未設定や取得失敗は、問題なしと区別する。必要人数の未設定件数は人数不足カード内に表示し、その他の未判定・一部未判定もカードに明示する。
- 保存済みから担当者が変わる日は「月全体」の折りたたみ一覧から選べる。「選択枠」には保存済みと現在案の担当者をコンパクトに左右表示し、追加・解除を色と + / − で示す。必要人数・備考はこの差分集計の対象外。差分用の履歴Stateは持たず、保存済みと現在案から導出する。
- 自動割当時に備考へ書かれた要確認は実行時の記録のまま。分析の現在案の判定とは分け、手動編集後も備考を自動では書き換えない。
